      9.1

      Reduce travel, retain meaning

      A reduced-motion alternative is a designed state change, not an empty version of the interface.

      Both panels receive the same notification or local route update. The full presentation slides and pops when global motion is enabled. The quieter presentation uses a short dissolve and persistent outline; under global reduction, both become static. A local checkbox can request more reduction, never override the global reduced setting.

      The system preference is observed live unless the shared header preference has been explicitly stored. A preference change cancels in-flight effects and reveals the committed state. Acknowledge updates both panels equally, and replay does not move keyboard focus. Meaning, status and available actions are independent of the animation.

      Try itReplay a route change, then switch motion off halfway through. Compare the text and acknowledge it from either panel. Change your system preference while this page remains open.

      Key idea

      State, focus and feedback stay the same. Remove spatial travel, not the result of the action.

      Pitfall

      Applying only a CSS media query while JavaScript keeps drawing transforms. Subscribe to live preference changes and cancel the runtime work as well.

      A stricter local preferenceJS
      import { motion } from '../core/motion.js';
function shouldReduce(localCheckbox) {
  return motion.reduced || localCheckbox.checked;
}
// Commit semantic state first. If shouldReduce is true, omit travel.
// On motion.subscribe, cancel existing effects and repaint that state.
      9.2

      Who can keep time while JS waits?

      The main thread runs your JavaScript and much of the rendering pipeline. A blocked task prevents it from responding.

      These lanes compare CSS transform, CSS left and a JavaScript requestAnimationFrame transform. A compositor-driven CSS transform may continue while the main thread is blocked. Left requires layout work; JS cannot update until its callback runs. Promotion and compositing depend on browser, layers and rasterization, so this is an observation opportunity, not a guaranteed outcome.

      The deliberate block lasts about two seconds and runs only after the warning button is activated. Two animation frames give its status and spinner a chance to paint first. The report records elapsed CPU-block time and the following rAF timestamp gap. It cannot measure visible FPS, compositor throughput or how many screen frames were missed.

      Try itStart the lanes, read the warning and explicitly choose Block. Compare what you saw with what the timestamps can prove. Pause, or enable reduced motion, before repeating.

      Key idea

      A long rAF gap proves the main-thread callback was delayed. It does not reveal what the compositor displayed during that delay.

      Pitfall

      Claiming transform always means GPU acceleration, or using JS timestamps as a visible-frame counter. Inspect a browser performance trace for deeper evidence.

      An honest gap instrumentJS
      let previous;
function observeTimestamp(now) {
  const gap = previous === undefined ? null : now - previous;
  previous = now;
  return gap; // milliseconds between JS callbacks, not visible FPS
}
// Call from rAF only while an explicitly started study is active.
      9.3

      Compare work, not slogans

      Property choice changes the kind of work requested. It does not produce a universal winner on every device.

      Width changes layout; scaleX changes the visual width without changing allocation. Box-shadow animates shadow geometry, whereas an overlay can fade a prepainted shadow with opacity. The latter may trade paint work for layers and memory. This grid creates 150 small targets to make those tradeoffs inspectable without overflowing a phone.

      Play samples main-thread rAF intervals for at most three seconds. Mean, 95th percentile, longest interval and gaps above 50ms are computed from real timestamps. They are not reliable benchmarking, frame-loss counts or compositor FPS. Backgrounding, refresh rate, warm caches and other tabs affect the result. Reduced motion samples a static baseline instead of animating.

      Try itPlay Width, then Transform. Repeat with Shadow and Overlay opacity. Turn targets off for a baseline. Compare results without declaring a speed ratio or a winner.

      Key idea

      Measure the actual property path with a bounded, repeatable workload. Label the instrument’s limits next to its numbers.

      Pitfall

      A smooth JS callback stream does not prove every pixel was presented on time. A noisy sample is not evidence that one property is always worse.

      Interval summaryJS
      function summarize(intervals) {
  if (!intervals.length) return null;
  const sorted = [...intervals].sort((a, b) => a - b);
  return {
    mean: intervals.reduce((a, b) => a + b, 0) / intervals.length,
    p95: sorted[Math.ceil(sorted.length * 0.95) - 1],
    longest: sorted[sorted.length - 1],
    longGaps: intervals.filter(ms => ms > 50).length
  };
}
      9.4

      Read together, write together

      A layout read after a layout write can force the browser to resolve pending geometry before your code continues.

      Both runs reset 150 rows to 100px, read each row’s offsetWidth and set its width to that value plus 20px. The interleaved version alternates reads and writes. The batched version takes all measurements before any writes. Both explicitly read final geometry before stopping the timer; reset work is excluded.

      Three bounded repetitions produce a measured median, with a task boundary between repetitions. Buttons are disabled while a run is active. The sandbox verifies every final width and compares the two outcomes after both methods have run. Timing is approximate and device-dependent; no deterministic speed gain is promised. This is synchronous layout work, not a measure of all subsequent paint.

      Try itRun Interleaved, then Batched. Confirm identical 120px outcomes before comparing milliseconds. Reset and reverse the run order to expose warm-up effects.

      Key idea

      Batching preserves the same geometry work while reducing opportunities for repeated forced layout.

      Pitfall

      Comparing different outcomes or including reset costs in only one timing. Verify parity and avoid asserting a required speed ratio in tests.

      Same work, different orderJS
      function interleaved(rows) {
  for (const row of rows) {
    const width = row.offsetWidth;
    row.style.width = `${width + 20}px`;
  }
}
// Caller resets widths to 100px first.
      function batched(rows) {
  const widths = rows.map(row => row.offsetWidth);
  rows.forEach((row, i) => {
    row.style.width = `${widths[i] + 20}px`;
  });
}
// Caller reads final layout before ending timing.
      9.5

      Focus arrives before its decoration

      Keyboard users do not need to watch a ring travel to discover where their next keypress will go.

      These are four native controls: two buttons, an input and a select. Tab determines focus; this study never intercepts it or changes the tab order. The native focus-visible outline appears immediately. A pointer-events: none overlay adds an optional moving shadow, not a replacement focus indicator.

      The overlay measures the focused control relative to its local container, including scroll offsets. Scroll and resize snap its geometry rather than animate a stale position. Blur hides the supplemental ring; reduced motion cancels travel and places it immediately. The actual focused element and its native outline remain authoritative.

      Try itTab through all four controls, type a note and choose a format. Scroll the page while focused, resize it, then turn motion off. Focus should never move because of the ring.

      Key idea

      Focus is a browser state, not a location inferred from animation. Keep the native ring visible throughout the glide.

      Pitfall

      Removing outline because a custom ring exists. The overlay can lag, clip or fail; native focus must still remain usable and visible.

      Decorative, never interactiveCSS
      .supplemental-ring {
  position: absolute;
  pointer-events: none;
  transform-origin: 0 0;
  box-shadow: 0 0 0 6px rgb(69 227 184 / 30%);
}
:focus-visible { outline: 2px solid #d4ff4f; outline-offset: 3px; }
/* Geometry follows focusin; it never calls focus() itself. */
      Chapter recap

      What to remember

      1. Keep meaning without travel. Live preferences cancel runtime effects, not just CSS transitions.
      2. Know the instrument. JS callback gaps cannot count compositor frames or prove visible smoothness.
      3. Experiments require consent and bounds. Nothing blocks automatically; loops stop offscreen.
      4. Batch equivalent work. Verify DOM parity before interpreting approximate timing.
      5. Native focus is primary. Supplemental motion must never delay or steal it.
