    Easing & curves

    Duration says how long; easing says how. The curve decides where the time is spent, whether motion launches or lands, glides or snaps. Learn to read curves at a glance, pick them by intent, and author the ones cubic-bezier cannot express.

      2.1

      Why linear looks robotic

      Nothing in the physical world starts or stops instantly. Linear motion does both, and the eye notices within a single frame.

      A linear animation jumps from standing still to full speed on its first frame and stops dead on its last. That infinite acceleration is what reads as mechanical. Easing redistributes progress over time so that velocity ramps instead of switching on and off.

      Look at the velocity plots under each track. Linear is a flat box with vertical walls. Ease-out starts fast and glides down to zero, which is exactly what an object with mass does as it comes to rest.

      Linear still has honest jobs: progress bars that mirror real work, continuous rotation such as spinners, marquees, and colour or opacity changes where there is no sense of mass to betray.

      Try itWatch only the right-hand end of each track. The linear card slams into place; the eased card settles. Then pause and compare the shapes of the two velocity plots.

      Key idea

      Velocity should rise and fall smoothly. Ease-out for arrivals, ease-in for departures, ease-in-out for movement between two points on screen.

      Pitfall

      Hand-rolled JavaScript animation is linear by default: x += speed * dt has constant velocity. Compute linear progress, then pass it through an easing function.

      How it’s builtJS 
      const easeOutCubic = (t) => 1 - Math.pow(1 - t, 3);

function slide(el, distance, duration) {
  const start = performance.now();
  requestAnimationFrame(function frame(now) {
    const t = Math.min((now - start) / duration, 1); // linear time, 0 to 1
    const progress = easeOutCubic(t);                  // eased progress
    el.style.transform = `translateX(${progress * distance}px)`;
    if (t < 1) requestAnimationFrame(frame);
  });
}
      2.2

      The easing families

      Easing functions come in families. Learn their shapes once and you can read any curve at a glance.

      Quad, cubic and quart are polynomials (t², t³, t⁴): each step up makes the acceleration more dramatic and the tail longer. Expo is exponential rather than a power of t, the most extreme of the everyday curves, and circ follows a quarter circle. Each family comes in three flavours: in (slow start), out (slow end) and in-out (both).

      Expressive curves add character. Back and elastic leave the box to overshoot the target, which reads as energy or elasticity. Bounce never goes past the target; it stays inside the box and strikes the top edge several times, like a ball dropped onto its resting place.

      To read a curve, remember that the horizontal axis is time and the vertical axis is progress. Steep means fast, flat means slow, and any part of the curve above the dashed box has gone past the target.

      Try itHover or tap the cards. Compare Out quad with Out expo: same destination, completely different confidence. Filter to In-out and notice how all of them are symmetric.

      Key idea

      Steep is fast, flat is slow, outside the box overshoots. Out curves are the workhorses for interface arrivals; keep back, elastic and bounce for moments of delight.

      Pitfall

      Elastic and bounce on functional UI. They are charming the first time and slow people down every time after that.

      How it’s builtJS 
      // Polynomial families use powers of t. "Out" is "in" flipped: out(t) = 1 - in(1 - t).
const easeInCubic = (t) => t * t * t;
const easeOutCubic = (t) => 1 - Math.pow(1 - t, 3);
const easeInOutCubic = (t) =>
  t < 0.5 ? 4 * t * t * t : 1 - Math.pow(-2 * t + 2, 3) / 2;

// Expo is exponential, not a power of t.
const easeOutExpo = (t) => (t === 1 ? 1 : 1 - Math.pow(2, -10 * t));

// Back overshoots: it briefly returns values above 1.
const easeOutBack = (t) => {
  const c1 = 1.70158;
  return 1 + (c1 + 1) * Math.pow(t - 1, 3) + c1 * Math.pow(t - 1, 2);
};
      2.3

      Choose the curve by direction

      The direction of travel picks the curve: arrive with ease-out, leave with ease-in, and move across the screen with ease-in-out.

      An entrance with ease-in accelerates into its resting place and stops at full speed, so it crashes. An exit with ease-out spends its slowest moments right at the edge of the screen, so it lingers. Linear movement between two visible points starts and stops with a jolt.

      Match the curve to the story. Deceleration means arriving, acceleration means leaving, and a symmetric curve means travelling between two places the user can see.

      Try itPlay all six at once, then watch one column at a time. The bottom row is not broken; it simply feels off. That small wrongness is exactly what users sense and cannot name.

      Key idea

      Enter: ease-out. Exit: ease-in. On-screen move: ease-in-out. Combine with chapter 01: exits are also shorter.

      Pitfall

      Using ease-in-out for everything because it is the default in many design tools. It is right for only one of the three cases.

      How it’s builtCSS 
      :root {
  --ease-enter: cubic-bezier(0.05, 0.7, 0.1, 1);  /* decelerate */
  --ease-exit: cubic-bezier(0.3, 0, 0.8, 0.15);   /* accelerate */
  --ease-move: cubic-bezier(0.65, 0, 0.35, 1);    /* symmetric */
}

.toast[data-state='entering'] { animation: toast-in 320ms var(--ease-enter) both; }
.toast[data-state='leaving'] { animation: toast-out 200ms var(--ease-exit) both; }
.card.is-moving { transition: transform 400ms var(--ease-move); }
      2.4

      Anatomy of cubic-bezier

      Every cubic-bezier() curve, including the keywords ease, ease-in and ease-out, is a cubic Bézier with its ends pinned at (0, 0) and (1, 1). You shape it with two handles. (steps() and linear() work differently; they come next.)

      The first handle (orange) shapes the start of the motion and the second (violet) shapes the end. The steeper the curve leaves a corner, the faster the motion is at that moment. Each handle has an x, which is time, and a y, which is progress. x must stay between 0 and 1 because time cannot run backwards, but y is free: pull a handle above the frame and the motion overshoots; pull it below and the motion winds up first.

      Under the hood the browser has to invert the curve. Given a moment in time x, it finds the parameter t where X(t) = x, then reads Y(t). Newton–Raphson converges in a few steps and a bisection fallback handles flat spots. Every preview in this lesson runs on that solver.

      Try itChoose Snap, then drag the orange handle above the top of the frame and watch the start overshoot. Focus a handle and use the arrow keys for precise nudges, with Shift for bigger steps.

      Key idea

      x values stay within 0–1; y values are free. A handle above 1 overshoots, a handle below 0 anticipates, and the angle a curve leaves each corner sets the speed there.

      Pitfall

      Trusting keyword names. CSS ease-out is cubic-bezier(0, 0, 0.58, 1), far gentler than the expo-style curves modern interfaces use, and the default ease is not symmetric at all.

      How it’s builtJS 
      // cubic-bezier(x1, y1, x2, y2) with endpoints fixed at (0,0) and (1,1)
function cubicBezier(x1, y1, x2, y2) {
  const coef = (p1, p2) => {
    const c = 3 * p1, b = 3 * (p2 - p1) - c;
    return { a: 1 - c - b, b, c };
  };
  const X = coef(x1, x2), Y = coef(y1, y2);
  const sample = (k, t) => ((k.a * t + k.b) * t + k.c) * t;
  const slope = (t) => (3 * X.a * t + 2 * X.b) * t + X.c;

  function solveT(x) {
    let t = x;                                // Newton-Raphson on X(t) = x
    for (let i = 0; i < 8; i++) {
      const error = sample(X, t) - x;
      if (Math.abs(error) < 1e-7) return t;
      const d = slope(t);
      if (Math.abs(d) < 1e-6) break;          // flat spot: Newton would jump away
      t -= error / d;
      if (t < 0 || t > 1) break;              // left the curve: stop trusting Newton
    }
    let lo = 0, hi = 1;                       // bisection always converges because
    t = x;                                    // X(t) is monotonic when x1, x2 are in [0, 1]
    for (let i = 0; i < 40; i++) {
      const value = sample(X, t);
      if (Math.abs(value - x) < 1e-7) break;
      if (value < x) lo = t; else hi = t;
      t = (lo + hi) / 2;
    }
    return t;
  }

  return (x) => (x <= 0 ? 0 : x >= 1 ? 1 : sample(Y, solveT(x)));
}
      2.5

      Beyond cubic-bezier: linear()

      A cubic Bézier can bend only so far: it can overshoot once, but it can never oscillate. linear() draws any curve from points, so bounces, elastics and real springs can run in pure CSS.

      linear() takes a list of progress values spread evenly over time (you can also pin a value to a percentage) and joins them with straight lines. With enough points the joins disappear. Because it is plain data, you can generate it from any function, including a physically simulated spring, and ship it as a CSS custom property.

      Detect support with CSS.supports() or @supports, not a browser version string. Keep a cubic-bezier fallback in production; this builder demonstrates a JavaScript fallback using the same function.

      Try itChoose Bounce and drag the sample points down to about 8. The curve becomes a visible polyline and the box stutters at the corners. Around 30–40 points is a useful starting point; compare against the dashed exact curve, especially at sharp rebounds.

      Key idea

      Generate linear() from real functions at build time or on start-up; 30–50 points is a starting point, not a guarantee. High-frequency oscillations, sharp corners and large travel may require more samples.

      Pitfall

      Putting an unsupported value in a custom property and expecting the previous declaration to win. The property becomes invalid at computed-value time and resets to the initial value, ease. Guard with @supports instead.

      How it’s builtJS + CSS 
      function linearFromFunction(fn, samples = 40) {
  const points = [];
  for (let i = 0; i <= samples; i++) points.push(Number(fn(i / samples).toFixed(4)));
  return `linear(${points.join(', ')})`;
}

document.documentElement.style.setProperty('--ease-bounce', linearFromFunction(easeOutBounce));

/* CSS:
.ball { transition: transform 800ms cubic-bezier(0.34, 1.56, 0.64, 1); }
@supports (transition-timing-function: linear(0, 1)) {
  .ball { transition-timing-function: var(--ease-bounce); }
}
*/
      2.6

      Stepped timing

      Not all motion should be smooth. steps() jumps between discrete states, which is exactly right for clocks, typewriters, sprites and counters.

      steps(n, position) divides the duration into n equal intervals and holds each value flat. The position keyword decides where each jump lands: jump-end (the default) waits a full interval before the first jump, jump-start jumps immediately, and jump-both / jump-none add or remove a step at the ends.

      A typewriter is steps(characters) on a width measured in ch with a monospace font; a blinking caret is steps(1); a sprite sheet is steps(frames) on background-position.

      Try itPress Replay and watch the white cursor cross the bars. jump-start is already a quarter full the instant it begins; jump-end waits a whole interval before its first jump.

      Key idea

      Use steps() for genuinely discrete states. For text, pair it with a monospace font and ch units so each step reveals exactly one character.

      Pitfall

      Stepped timing on the spatial movement of interface elements. It does not look retro; it looks like dropped frames.

      How it’s builtCSS 
      .typewriter {
  width: 28ch;                 /* the sentence is 28 characters long */
  overflow: hidden;
  white-space: nowrap;
  font-family: ui-monospace, monospace;
  animation: type 2.8s steps(28, end) both;
}
@keyframes type { from { width: 0; } }

.caret { animation: blink 1s steps(1) infinite; }
@keyframes blink { 50% { opacity: 0; } }

.second-hand { animation: turn 60s steps(60) infinite; }
@keyframes turn { to { transform: rotate(360deg); } }
      2.7

      Easing as design tokens

      Name your curves and durations once, then reuse them everywhere. Consistency is what makes motion feel designed rather than decorated.

      A small vocabulary covers most products: a standard curve for movement on screen, an enter (decelerate) and an exit (accelerate) curve, one emphasized curve for hero moments and perhaps one overshoot for playful confirmations. Pair them with three or four duration tokens.

      Engineers stop guessing, designers stop redlining milliseconds, and every surface of the product moves with the same accent. Changing the feel of the whole product becomes a one-line edit.

      Try itOpen the menu with Standard at Medium, then switch to Emphasized at Long, then Overshoot at Short. Same component, three different voices. Notice that closing always uses the exit token.

      Key idea

      Five curves and three or four durations cover most products. Define them as CSS custom properties and mirror them in your design tool.

      Pitfall

      One-off magic numbers copied from an old prototype and scattered across the codebase. They drift, and nobody remembers which ones were intentional.

      How it’s builtCSS 
      :root {
  --ease-standard: cubic-bezier(0.2, 0, 0, 1);
  --ease-enter: cubic-bezier(0.05, 0.7, 0.1, 1);
  --ease-exit: cubic-bezier(0.3, 0, 0.8, 0.15);
  --ease-emphasized: cubic-bezier(0.16, 1, 0.3, 1);
  --ease-overshoot: cubic-bezier(0.34, 1.56, 0.64, 1);
  --dur-short: 200ms;
  --dur-medium: 320ms;
  --dur-long: 500ms;
}

.menu {
  transition:
    transform var(--dur-medium) var(--ease-enter),
    opacity var(--dur-short) linear;
}
      Chapter recap

      What to remember

      1. Linear is for machines. Spatial motion needs velocity that ramps up and down.
      2. Read curves like graphs: steep is fast, flat is slow, above the box overshoots.
      3. Match the curve to the direction: enter with ease-out, exit with ease-in, move across the screen with ease-in-out.
      4. cubic-bezier is two handles: x stays within 0–1, y is free to overshoot or anticipate.
      5. linear() expresses any curve, including springs and bounces. Generate it, and guard it with @supports.
      6. steps() is for discrete states such as clocks, typewriters and sprites, never for interface movement.
      7. Tokenise curves and durations so the whole product speaks with one voice.
      Check yourself0/ 3

      A notification slides in from the top of the screen. Which curve fits?

      It is arriving, so it should decelerate into place. Ease-in would reach its resting position at full speed and stop abruptly.

      In cubic-bezier(x1, y1, x2, y2), which values may go outside the 0–1 range?

      x is time, which cannot run backwards, so it must stay within 0–1. y is progress, which may overshoot above 1 or wind up below 0.

      You want a real, oscillating spring feel in a pure-CSS transition. What do you use?

      A cubic-bezier can overshoot once but cannot oscillate. linear() samples the spring curve itself, wobbles included.
