    Micro-interactions

    A small movement makes a promise: I heard you, this is changing, here is what happened. Fourteen patterns turn those promises into explicit states, accessible controls and motion that can survive a change of mind.

      4.1

      Help before you judge

      Form feedback should reduce uncertainty, not punish someone for being halfway through typing.

      Separate a live hint from a verdict. A password meter can explain the rules as they become true, but its color cannot prove that a password is safe. This example counts four surface features; it is a heuristic, not entropy estimation, and cannot detect reused, breached or predictable passwords. Use invented text here. Nothing entered is logged, sent or persisted by these demos.

      An OTP looks like six boxes but represents one value. Paste, full-code autofill, backspace and arrow navigation must operate on that value without six separate chores. The local check below is deliberately explicit: editing during a pending check invalidates it, so an old success cannot overwrite a new code. A real authentication service would need entirely separate security, rate limiting and verification.

      Try itType an invented password and reveal it. Paste 314159 into any OTP cell, then submit 000000 and correct it while the local check is pending. Try the same path without a pointer.

      4.2

      A gesture is a negotiation

      Before an action is committed, movement should remain a reversible proposal.

      A pull moves through idle, pulling, armed, refreshing and complete. Resistance makes the threshold feel intentional; releasing below it does nothing destructive. A swipe first decides whether movement is horizontal. Vertical movement remains native scrolling, and revealing actions is distinct from executing them. Escape, pointer cancellation and lost capture all revert the proposal rather than accidentally committing it.

      Reordering has two coordinate systems: the document’s new order and the item’s visual position. FLIP measures the old rectangles, changes the DOM, then animates the difference back to zero. The dragged item stays under the pointer while neighbors make room. Move buttons perform the same reorder without requiring precision, and a cancel restores the original order.

      Try itPull just short of the threshold. Swipe the message left, delete it and undo. Drag the first itinerary stop below the last, then repeat and press Escape before releasing. Compare with Move down.

      4.3

      Reveal space, preserve context

      A panel has more than an open height. It has a trigger, a place in the focus order and a reason to exist.

      Update aria-expanded when the state changes, not when an animation ends. A closed panel is inert immediately, so a rapid Tab cannot enter disappearing controls. If focus was inside, move it to the trigger before hiding the panel. A grid track from 0fr to 1fr animates natural content height without guessing a maximum; reversing it naturally starts from the current rendered height.

      Search responds to explicit focus as well as clicks, and Escape closes it without instantly reopening from restored focus. A navigation disclosure is not an application menu: ordinary links keep their native Tab behavior. A wizard adds validation and progress to the same idea. Only the current step is enabled, and entering a new step places focus where the new task begins.

      Try itReverse the accordion before it finishes. Tab through the closed menu to verify its links are skipped. Escape from search. Advance the wizard with a blank name, then complete it with a keyboard.

      4.4

      Tell the truth about waiting

      A spinner means activity. A percentage means measured completion. Do not substitute one promise for the other.

      These examples simulate deterministic local chunks, so their percentages have a defined denominator. A real transfer should use actual completed bytes when available and switch to an indeterminate message when it cannot estimate. Cancellation is a first-class terminal state, not a brief animation on the way to an inevitable success. Reset invalidates all scheduled callbacks.

      The upload example uses a native file picker and a drop target, but only displays the filename: it does not read file contents or transmit anything. Skeletons solve a different problem. They reserve the final layout while content is unavailable, avoiding a geometry jump. Keep loading announcements outside the busy region so assistive technology can announce them immediately. Reduced motion stops shimmer and rotation; meaningful progress and cancellation still work.

      Try itCancel at 30%, wait beyond the original finish time, and confirm that success never appears. Replace a selected file mid-simulation. Replay the skeleton twice quickly and watch the unchanged card height.

  ring.setAttribute('aria-valuenow', progress);
  stroke.style.strokeDashoffset = 100 - progress;

      4.5

      Delight should clarify the action

      Expressiveness works best when it reinforces a useful distinction: selected versus unselected, nearby versus distant, active versus idle.

      A selectable chip is a button with a persistent pressed state, not a transient pop animation. Commit that state first, update the summary and then add a small scale accent. Repeated input cancels the previous accent; it never queues a delayed state change. Color is redundant with the checkmark and the accessible pressed value.

      The dock uses distance rather than a binary hover flag. Each icon’s target scale depends on the pointer’s distance from its stable button center, then a spring follows that scale. Only the icon grows: the hit target and label stay in place. Keyboard focus supplies an equivalent focal point. Under reduced motion, scale stays at one and the focus/selection styling carries the meaning.

      Try itToggle a chip several times quickly and read the summary. Sweep across the dock, then Tab into it and use Left and Right. Turn motion off while an icon is growing.

      Key idea

      Pitfall

      Scaling the hit-testing geometry itself, creating a feedback loop where growth moves the target and triggers a different hover. Measure stable wrappers; animate their children.

      How it’s builtJS
      const distance = pointerX - buttonCenter;
const influence = Math.exp(-(distance * distance) / (2 * 65 * 65));
spring.target = 1 + 0.55 * influence;
if (motion.reduced) spring.set(1);
icon.style.transform = `scale(${spring.step(dt)})`;
// Measure the stable button, never the scaled icon.
      Chapter recap

      What to remember

      1. Name the states first. Editing, checking and confirmed are different promises.
      2. Cancellation is not completion. Discard pending callbacks and restore a known proposal or partial result.
      3. Gestures need alternatives. Buttons, paste and native inputs often outperform custom movement.
      4. Focus belongs to the state machine. Hidden controls are inert; closing returns focus when needed.
      5. Work drives progress. Clearly label simulations and avoid suggesting real authentication or persistence.
      6. Keep meaning without motion. Static checks, text, focus rings and accurate ARIA outlast the animation.
