    Scroll-driven motion

    Sometimes scrolling starts the clock. Sometimes scrolling is the clock. Learn to tell those relationships apart, preserve the user's control and progressively enhance the same behavior across browsers.

      6.1

      Who owns the clock?

      A scroll-triggered entrance runs on time after crossing a threshold. A scroll-linked pose is a direct function of position.

      The left box starts a 600ms entrance once half of its slot is visible inside the left scroller. Stop scrolling and it still finishes. The right box samples scrollTop ÷ (scrollHeight − clientHeight): stop scrolling and it stops changing. Scroll backward and it reverses, while the left keeps its completed entrance.

      Each panel owns its own scrolling and keyboard focus. The observer's root is the left panel, not the page viewport. Native PageDown, Home and End remain available; there is no wheel listener that redirects your movement.

      Try itFocus the left panel and press End, then Home. Repeat on the right. Reset both and stop the left panel immediately after the box enters: its time-based entrance continues.

      Key idea

      Trigger is an event; link is a mapping. Only a linked animation naturally reverses with scrolling.

      Pitfall

      Observing a nested target against the page, or measuring page scroll for a panel-owned animation. The source must match the interaction.

      How it’s builtJS
      const observer = new IntersectionObserver(onThreshold, {
  root: leftScroller, threshold: 0.5
});
observer.observe(stableSlot); // animate its child, not the observed geometry
const range = rightScroller.scrollHeight - rightScroller.clientHeight;
const p = range > 0 ? clamp(rightScroller.scrollTop / range, 0, 1) : 0;
      6.2

      Depth comes from relative speed

      Parallax works when nearby layers move more than distant ones. The scene reads as depth because the rates differ, not because every layer travels far.

      This landscape uses page scroll, measured while its own rectangle passes through the viewport. The sun moves least, the clouds a little more and the foreground ridge most. The depth control scales those differences without changing the page's scroll range or intercepting input.

      Keep the scene clipped and give each layer enough coverage to avoid revealing an empty edge. Under reduced motion, all layers return to a pleasant static composition. A decorative mountain does not need to move for the lesson to remain understandable.

      Try itSet depth to 2× and scroll the page slowly across the scene. Compare with 0×, then turn motion off. Scrolling inside another demo should not move these layers.

      Key idea

      Use local progress and relative rates. Depth is a relationship among layers.

      Pitfall

      Applying raw document scroll to every scene. A scene far down the page then begins with a huge, arbitrary offset.

      How it’s builtJS
      const rect = scene.getBoundingClientRect();
const p = clamp((innerHeight - rect.top) / (innerHeight + rect.height), 0, 1);
const offset = (p - 0.5) * 56 * depthSpeed;
layer.style.transform = motion.reduced ? 'none'
  : `translateY(${offset * layerDepth}px)`;
      6.3

      Pin the reference, not the reader

      A sticky chart can keep a comparison in view while the explanation changes around it.

      The three passages below describe an illustrative design project, not real research. Each step supplies a new set of values for access, speed and trust. Between steps, the chart interpolates the adjacent states using measured paragraph positions. The stable chart makes the differences easier to compare.

      The page keeps native scrolling. Jump buttons provide a direct route to each step, and the headings receive focus. Under reduced motion, sticky positioning and long spacer passages collapse; the same content stays visible and the buttons select static chart states.

      Try itScroll slowly from Baseline to Revision, then reverse. Jump straight to Review. Toggle reduced motion and verify that all three explanations and the controls remain reachable.

      Key idea

      Sticky is a layout relationship. Keep the chart inside its story container so it releases naturally at the end.

      Pitfall

      Leaving several empty viewport heights after removing animation for reduced motion. Collapse the travel space as well as unpinning the chart.

      How it’s builtJS
      const fraction = clamp((readingLine - currentTop) / (nextTop - currentTop), 0, 1);
const value = lerp(states[step][bar], states[step + 1][bar], fraction);
// CSS position: sticky keeps the chart in its own story container.
// Reduced motion: position: static; passage min-height: 0.
      6.4

      Reveal the value, not a fiction

      A count-up is a presentation of a known number. It is not a live estimate of work being completed.

      This fictional study plan contains 72 reading cards, 48 practice cards and 90 review cards, each shown against a capacity of 100. The first full-motion view reveals those targets over 850ms. Easing slows the arrival, but every intermediate value is clamped so it can never exceed the target.

      Assistive technology receives the final quantities as static text. The changing digits and bars are decorative; a status announces completion only at the end. Replay restarts the presentation, not the underlying plan. Reduced motion shows the known values immediately.

      Try itReplay twice before the first run finishes. Confirm that the final quantities remain 72, 48 and 90. Scroll away during the reveal, return and compare with reduced motion.

      Key idea

      Data owns the target. Animation only renders the approach; it cannot improve or invent the result.

      Pitfall

      Putting every changing digit in an aria-live region, or using overshooting easing to briefly claim more than the actual quantity.

      How it’s builtJS
      const p = clamp(elapsed / 850, 0, 1);
const eased = 1 - (1 - p) ** 3;
const current = clamp(Math.round(target * eased), 0, target);
number.textContent = current; // aria-hidden visual digits
bar.style.transform = `scaleX(${current / 100})`;
if (p === 1) status.textContent = 'All known quantities revealed.';
      6.5

      Let the browser own the timeline

      A native scroll timeline replaces elapsed seconds with the progress of a scroll source.

      Both animated elements here are descendants of the same nested scroller. Their timeline is scroll(nearest block), with a 0–100% range. The progress line scales from empty to full, and the card travels from its origin to a measured endpoint. Moving the page does not change their source.

      Support detection checks timeline and range syntax. When available, CSS renders the animation without JavaScript sampling its pose each frame. The forced fallback uses passive scroll events and the shared ticker to write the same transforms; it is useful but not independent of the main thread. Reduced motion retains the progress line and removes card travel in either mode.

      Try itScroll to End, toggle Force JS fallback, then press Home. Compare both endpoints and the midpoint. Toggle at a nonzero position: it should not reset your place.

      Key idea

      Declare the animation before its timeline. The shorthand resets timeline properties, so declaration order matters.

      Pitfall

      Comparing a page-root native timeline with a panel-root fallback. Similar-looking motion can hide different denominators.

      How it’s builtCSS
      @supports (animation-timeline: scroll()) and (animation-range: 0% 100%) {
  .sc-native[data-engine='native'] .sc-native-progress {
    animation: sc-fill 1s linear both;
    animation-timeline: scroll(nearest block);
    animation-range: 0% 100%;
  }
}
@keyframes sc-fill {
  from { transform: scaleX(0); }
  to { transform: scaleX(1); }
}
      6.6

      Velocity is an accent, not a steering wheel

      Position tells you where the reader is. Velocity tells you how quickly, and in which direction, they are moving.

      These local cards skew according to a signed, low-pass-filtered velocity measured in pixels per second. Downward movement is positive; upward movement is negative. Sensitivity converts that velocity to degrees, capped at ±8° so the content remains legible.

      When scrolling stops, the input velocity becomes zero and the filtered response decays to rest. The animation changes only the cards' presentation, never scrollTop or wheel displacement. Pause and reduced motion both remove skew while leaving the scroller fully usable.

      Try itScroll down quickly, reverse, then stop. Watch the signed angle return to zero. Increase sensitivity, pause the effect and verify that PageDown still scrolls normally.

      Key idea

      Filter and clamp a signed velocity. Decay toward zero when input stops, rather than leaving the last skew frozen.

      Pitfall

      Using pixels per frame as velocity. At 120Hz the same gesture would produce half the effect; divide by elapsed seconds.

      How it’s builtJS
      const raw = dt > 0 ? (scroller.scrollTop - previousTop) / dt : 0;
velocity = damp(velocity, clamp(raw, -6000, 6000), 12, dt);
const angle = clamp(velocity / 1000 * sensitivity, -8, 8);
card.style.transform = motion.reduced ? 'none' : `skewY(${angle}deg)`;
// Continue sampling zero input until settled, then stop the shared-loop subscription.
      Chapter recap

      What to remember

      1. Trigger versus link is a clock decision. Time continues; position can reverse.
      2. Measure the actual owner. Nested scrollTop and page progress are not interchangeable.
      3. Pin a reference, not the user. Native scrolling and jump controls stay available.
      4. Reveal known values honestly. Clamp counts and announce only meaningful results.
      5. Enhance progressively. Native and fallback modes need identical ranges and endpoints.
      6. Remove decoration, retain control. Reduced motion keeps useful progress and functional scrollers.
      Check yourself0/ 3

      You scroll backward. Which relationship naturally rewinds?

      A linked pose is a function of position. The triggered entrance has its own elapsed-time clock after the event.

      What denominator describes a nested scroller's available range?

      Use the actual source's scrollable distance, and guard a zero range. This must agree in native and fallback modes.

      What should reduced motion change in the native study?

      Meaningful data can still follow input directly. Decorative travel is optional; truthful progress and control are not.
