    Springs & physics

    Durations are guesses about how long motion should take. Physics answers the question for you, and it keeps answering correctly when the user changes their mind halfway through. This chapter builds intuition for springs, momentum, friction and gravity, one demo at a time.

      3.1

      Anatomy of a spring

      A spring has no duration. It has stiffness, damping and mass, and the duration falls out of the physics.

      Hooke’s law pulls the weight towards its resting point with a force proportional to the distance, −k·x. Damping resists motion with a force proportional to velocity, −c·v. Divide by the mass and you have the acceleration for the next instant.

      a = (−k·x − c·v) / m     ζ = c / (2√(k·m))

      Stiffness sets how hard the spring pulls: higher is snappier. Damping drains energy. Increasing mass at fixed k and c lowers the natural frequency, ω₀ = √(k/m), but also lowers the damping ratio: the response becomes slower and relatively more oscillatory, not simply calmer. From a displaced, zero-velocity start, ζ below 1 oscillates, 1 is critical, and above 1 approaches without oscillating. A large initial velocity can still carry a critical or overdamped spring past its target.

      Try itGrab the weight and throw it. Then set damping to 0 and press Kick it: without damping it never stops. Finish with the Molasses preset to feel an overdamped spring.

      Key idea

      Tune springs with stiffness and damping, not milliseconds. The damping ratio ζ tells you whether it will bounce before you ever run it.

      Pitfall

      Inventing new spring values for every component. Define three or four presets (gentle, default, snappy, wobbly) and reuse them, exactly like easing tokens.

      How it’s builtJS 
      // Semi-implicit Euler needs a small timestep relative to the spring frequency.
// It is NOT unconditionally stable; substep stiff systems (e.g. dt = 1/240).
function stepSpring(s, dt) {
  const force = -s.stiffness * (s.value - s.target) - s.damping * s.velocity;
  s.velocity += (force / s.mass) * dt;   // update velocity first...
  s.value += s.velocity * dt;            // ...then position with the new velocity
}

// Kinetic's Spring uses the exact closed-form solution within each frame.
// For a fixed target this avoids integration error. Moving targets are still
// sampled per frame, and long frames are capped to avoid background jumps.
const spring = new Spring({ stiffness: 180, damping: 12, mass: 1 });
spring.target = 1;
onFrame((dt) => render(spring.step(dt)));
      3.2

      Built for interruption

      Interfaces are interrupted constantly: users tap again before the first animation has finished. Springs handle it gracefully; restarted tweens do not.

      A tween is defined by a start, an end and a duration. This demo restarts a 450ms cubic in-out tween from its current position. That particular curve starts at zero velocity and does not overshoot, so every retarget discards momentum. This is not a property of all tweens: a back curve can overshoot, and a velocity-aware interpolator can preserve the incoming slope.

      A spring has no timeline to restart. Changing its target only changes the force acting on it, so its current velocity carries straight into the new motion. The path bends instead of breaking.

      Try itClick quickly at different points in the stage, or turn on Auto retarget. Watch the velocity traces: the tween’s line snaps to zero at every change, while the spring’s line stays continuous.

      Key idea

      Anything the user can interrupt (drags, toggles tapped twice, hover in and out) deserves velocity-preserving motion: springs, or tweens that start from the current velocity.

      Pitfall

      Assuming that reversing any CSS transition preserves velocity. Browsers have reversal-shortening rules, but the new velocity depends on the chosen easing and interruption point. Test rapid reversals rather than inferring continuity from the duration alone.

      How it’s builtJS 
      // Tween: restarting from the current position throws velocity away.
function retargetTween(target) {
  tween = { from: currentX, to: target, start: performance.now(), duration: 450 };
}

// Spring: only the target changes; velocity carries into the new motion.
function retargetSpring(target) {
  spring.target = target;
}

onFrame((dt) => {
  spring.step(dt);
  ball.style.transform = `translateX(${spring.value}px)`;
});
      3.3

      Three ways to come to rest

      Damping is a relationship, not a magic number. Release three identical masses from rest and only change the damping ratio.

      Below ζ = 1, the system trades kinetic and spring energy several times before damping removes it: the trace crosses the dashed target. At ζ = 1, the two characteristic decay rates meet. Above 1, one slow decay dominates, so adding damping can actually make the last part of the journey take longer.

      Critical damping is the fastest nonoscillatory return for the typical displaced, zero-velocity start at fixed stiffness and mass. It is not a promise that every release avoids overshoot. A strong incoming throw changes the initial conditions. The times below measure when position stays within 2% of the travel; a production spring should also check velocity before sleeping.

      Try itRelease all three. Identify the first target crossing, then compare the critical and overdamped tails. With motion off, read the complete traces instead of watching the balls.

      Key idea

      Choose the regime before tuning the feel. Critical is a useful baseline for precise controls; underdamping communicates elasticity, and overdamping can communicate resistance.

      Pitfall

      Increasing damping indefinitely to make something faster. Past critical, more damping produces a longer tail. Initial velocity also matters.

      How it’s builtJS
      const stiffness = 170, mass = 1;
const criticalDamping = 2 * Math.sqrt(stiffness * mass);
const damping = zeta * criticalDamping;
const position = springPosition(time, {
  stiffness, damping, mass, from: 0, to: 1, velocity: 0,
}); // sample the same initial conditions for every trace
      3.4

      Snap where the throw is going

      A release position describes where the finger was. Release velocity describes what the person meant to do next.

      For exponential friction, velocity decays as v₀e−kt. Integrating that curve gives a projected resting position, x + v/k. Higher friction shortens the throw. The dashed marker is that free-decay estimate, clamped to the stage; a wall collision changes the subsequent path.

      With snapping enabled, choose the target nearest the projected rest, then hand current position and velocity to a spring. This makes a fast flick pass the midpoint without demanding a long drag. The estimate is not a timer, and the spring’s settling time is not the friction model’s stopping time.

      Try itThrow the puck gently, then flick it from almost the same position. Enable snapping and compare destinations. Focus the puck and use arrows for equivalent throws; Escape cancels a grab.

      Key idea

      Project first, select second, settle third. Intent selection and the motion that reaches the destination are separate decisions.

      Pitfall

      Using the last pointer delta as velocity. A tiny pause or a sparse event can dominate it. Sample a short recent window, cap the result, and discard momentum on cancellation.

      How it’s builtJS
      const projectedX = x + velocity / friction;
const destination = nearest(projectedX, targets);
spring.value = x;
spring.velocity = velocity; // preserve the throw
spring.target = destination;
// Reduced motion: set the destination directly instead of coasting.
if (motion.reduced) spring.set(destination);
      3.5

      Make a boundary feel like a boundary

      Rubber banding acknowledges a pull without pretending there is more content beyond the edge.

      Inside the list, finger travel maps to content travel one-to-one. Outside it, a bounded function compresses the excess displacement. Here f(x) = sign(x) · d · (1 − 1/(1 + 0.55|x|/d)), with viewport height d. Its initial slope is 0.55, not 1, and the resistance increases as the pull grows.

      On release, the boundary becomes a spring target. On regrab, invert the resistance mapping before adding new pointer travel; otherwise the already-compressed display position is compressed a second time. Turning the effect off must clamp immediately, zero velocity and reanchor an active drag. Motion reduction removes the animated return and inertia, not the ability to move through the list.

      Try itPull down at the top, release, and grab again before the return finishes. Toggle rubber banding off during a pull. Focus the list and use Up, Down, Home and End.

      Key idea

      Keep raw input, rendered displacement and legal bounds distinct. Each has a different job in a continuous gesture.

      Pitfall

      Reusing the rendered overscroll as raw input after interruption. That causes a jump on the first move, even when the pointer barely moves.

      How it’s builtJS
      // Recover raw excess from displayed excess when regrabbing.
const rawExcess = shown * height / (0.55 * (height - Math.abs(shown)));
// Disabling resistance is a state change, not another spring target.
offset = clamp(offset, minOffset, 0);
velocity = 0;
spring.set(offset);
drag.startY = drag.currentY;
drag.startRaw = offset;
      3.6

      Collisions spend energy

      Gravity accelerates a ball; restitution decides how much of its incoming normal velocity survives the impact.

      A floor collision uses v′ = −ev. At e = 0, normal motion is lost; near 1, it is mostly returned. The fraction of normal kinetic energy retained is e², not e. Circle collisions share an impulse according to inverse mass, after separating overlaps along the collision normal.

      This small teaching solver advances at 120Hz with capped catch-up time. Coincident centers need a deterministic nonzero normal, and overlap correction must be followed by boundary clamping. Squash is only a brief drawing transform: it never changes the collision radius. Stacks can keep exchanging tiny impulses; use Pause to stop them explicitly. The simulation also pauses out of view and in hidden tabs. Reduced motion places balls in a static arrangement.

      Try itDrop several balls at the same spot. Compare restitution 0.2 and 0.85, then pause a collision. Focus the canvas and press Enter or Space to drop; Clear removes every ball.

      Key idea

      Separate simulation geometry from visual deformation. A squash can sell the impact without destabilizing the solver.

      Pitfall

      Dividing a zero center-distance by a tiny substitute but leaving both normal components zero. Nothing separates. Pick a deterministic axis when centers coincide.

      How it’s builtJS
      const distance = Math.hypot(dx, dy);
const nx = distance > 0.0001 ? dx / distance : 1;
const ny = distance > 0.0001 ? dy / distance : 0;
const vn = (b.vx - a.vx) * nx + (b.vy - a.vy) * ny;
if (vn < 0) {
  const impulse = -(1 + restitution) * vn / (1 / a.mass + 1 / b.mass);
  a.vx -= impulse * nx / a.mass;
  b.vx += impulse * nx / b.mass;
  a.vy -= impulse * ny / a.mass;
  b.vy += impulse * ny / b.mass;
} // separate overlaps and clamp both circles back inside the world too
      3.7

      Pass the motion downstream

      One spring follows the pointer. The next follows the first spring. Twelve links turn a single input into a flowing trail.

      Every link owns position and velocity in two axes. It targets the preceding link’s current position, not the original pointer position; this is what creates phase lag down the chain. Higher stiffness transmits a change quickly, while low damping allows waves of overshoot to travel behind it.

      This is a one-way follower chain, not a rope with distance constraints or equal-and-opposite forces. We substep the coupled updates so the tail is less dependent on display rate. The trail sleeps when settled; there is no idle sine animation. With reduced motion, the head tracks direct input and the links form a static, compact trail. Keyboard arrows move the same target.

      Try itDraw a sharp corner, stop, and watch the tail catch up. Increase damping to remove the ripples. Focus the canvas and trace a square with the arrow keys; Home recenters it.

      Key idea

      Local rules create a global gesture. Follow a neighbor when you want propagation; follow the same target when you want coordinated arrival.

      Pitfall

      Calling a decorative follower chain a physically accurate rope. Constraints, collisions and bidirectional forces require a different model.

      How it’s builtJS
      // Repeat with small substeps for a moving, coupled target.
links.forEach((link, i) => {
  const leader = i === 0 ? pointer : links[i - 1];
  link.x.target = i === 0 ? leader.x : leader.x.value;
  link.y.target = i === 0 ? leader.y : leader.y.value;
  link.x.step(dt);
  link.y.step(dt);
});
if (links.every(link => link.x.isSettled() && link.y.isSettled())) loop.stop();
      Chapter recap

      What to remember

      1. Tune relationships. Mass changes both natural frequency and damping ratio when k and c stay fixed.
      2. Preserve velocity on retarget. Cancellation is different: discard the throw and restore a legal state.
      3. Project intent before snapping. A destination choice is separate from the spring that reaches it.
      4. Keep raw and rendered input distinct. Invert resistance on regrab and reanchor when bounds change.
      5. Budget numerical work. Small fixed steps, deterministic collision normals and post-correction clamps prevent common failures.
      6. Provide static equivalents and a way to stop. Reduced motion still permits direct manipulation and meaningful results.
      Check yourself0/ 3

      At fixed stiffness and damping, increasing mass does what?

      Both √(k/m) and c/(2√(km)) decrease. Slower does not necessarily mean less oscillatory.

      A spring is retargeted mid-flight. What should be retained?

      The new target changes acceleration, not the current state. Keeping velocity avoids an artificial stop.

      Rubber banding is disabled during overscroll. What is truthful?

      The off state must already obey hard bounds. Reanchoring prevents a jump on the next pointer move.
