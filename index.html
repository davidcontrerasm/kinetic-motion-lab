00 — Manifesto

Motion is not decoration. It is the connective tissue of an interface. It explains where things come from, confirms what just happened, and quietly directs attention to what matters next. Every duration, every curve, every delay is a design decision.

02 — Micro-interactions

Small moments, big feelings.

Twelve tiny components, each tuned for one job: feedback, affordance, state change or delight. They are all live, keyboard accessible and respect reduced-motion.

Press and hold — release early to rewind

02.01

Hold to confirm

Deliberate friction for destructive actions. Progress fills while pressed and rewinds faster when released.

  • RationaleDeliberate friction gives a destructive-looking action time to be cancelled. This demo deletes no data.
  • TimingKeep holding to complete; release early and progress rewinds faster than it filled.
  • MechanismPress state drives a progress value, a scaled fill and a clipped label overlay; completion replaces the trash icon with a check.
02.02

Like burst

Anticipation, pop and particles reward the action; the counter rolls in the direction of change.

  • RationaleThe filled heart and pressed state carry the answer after the celebration ends.
  • TimingA brief squeeze precedes the pop; the ring and particles disperse while the new count remains.
  • MechanismA native button toggles aria-pressed, heart classes and a shared rolling counter. Clicking again removes the like.

02.03

Squash & stretch switch

The thumb stretches while pressed and springs across; the whole scene answers the state change.

  • RationaleThe thumb, scene and Day/Night caption all describe the same selected state.
  • TimingStretch lasts only while pressed. Spring-shaped travel settles before the slower sky transition finishes.
  • Mechanismaria-checked selects the endpoint; CSS widens the active thumb and translates it using the shared spring easing, with a cubic-bezier fallback.

02.04

Morphing submit

One element carries the whole journey: idle, loading and success, so attention never has to jump.

  • RationaleIdle, loading and done occupy the same location, keeping attention on the result.
  • TimingLoading appears before the simulated work completes; success holds briefly before the button returns to idle.
  • Mechanismdata-state coordinates width, spinner and check, alongside a live status message. A local timer simulates sending; no message or network request is sent.

1 of 3 done

02.05

Drawn checkboxes

Strokes draw on, labels strike through and progress eases forward. Completion earns a celebration.

  • RationaleEach check confirms one choice; the bar and text explain how much of the whole list is done.
  • TimingThe box responds first, then its check draws and the label strikes through. Aggregate progress eases to the new fraction.
  • MechanismNative checkbox state styles an SVG dash offset and label line. JavaScript counts checked inputs and scales the progress bar.

02.06

Floating label & validation

The label makes room instead of vanishing. Errors shake (a universal “no”), success draws a quiet check.

  • RationaleA persistent label gives context; the textual error explains what a shake alone cannot.
  • TimingValidation follows an attempt to validate or leaving the field, then updates while correcting the input rather than waiting for another submission.
  • MechanismLocal email-format checking selects error or valid state, updates the described live message and draws a check. It does not verify that an address exists.
02.07

Elastic tab indicator

The leading edge moves first and the trailing edge catches up, while content slides in the direction of travel.

  • RationaleThe indicator connects old and new selection; content direction preserves the order of destinations.
  • TimingThe leading edge starts first and the trailing edge catches up, briefly stretching the pill.
  • MechanismMeasured tab bounds set the pill’s left and right edges. Selection updates roving focus, aria-selected and the shared panel’s label.

Rate your experience

02.08

Expressive rating

Hover previews, click commits. A spring-driven face mirrors the score, so the input has an emotional echo.

  • RationalePreview lets someone inspect a score before committing; leaving the stars restores the selected rating.
  • TimingThe face follows a spring rather than waiting for a fixed animation to finish, so rapid reversals remain responsive.
  • MechanismThe radio group stores selection separately from hover preview. A shared mood value shapes the SVG eyes, mouth and color, with a textual rating alongside.

Hold a button to accelerate — limits push back

02.09

Rolling stepper

Digits roll in the direction of change. Holding accelerates, and hitting a limit gives a small, honest refusal.

  • RationaleDirectional digits explain increase versus decrease; a refusal at the limit avoids inventing an unavailable value.
  • TimingA press steps once, then holding repeats more rapidly. Release stops the repetition.
  • MechanismA bounded numeric value feeds the shared rolling-number widget. Hold scheduling accelerates updates; limit feedback leaves the value unchanged.

02.10

Copy confirmation

An icon morph plus a springy tooltip: the smallest possible “done”, right where the eye already is.

  • RationaleConfirmation beside the source avoids sending attention to a distant alert.
  • TimingCopy feedback is brief and returns to the reusable copy affordance.
  • MechanismThe shared clipboard helper tries the secure Clipboard API, then a temporary selected textarea and legacy copy command if unavailable or denied.

02.11

Pendulum slider

The value bubble hangs from the thumb and swings with its velocity: inertia you can feel through a pointer.

  • RationaleThe swinging label suggests inertia while the native range remains the authoritative value.
  • TimingFast changes excite the bubble; after input stops, the spring settles instead of snapping its angle back.
  • MechanismRange input positions the fill and bubble, while sampled change drives decorative rotation. Arrow keys update the same value and readout.

    Ring it · hover the stack · swipe to dismiss

    02.12

    Stacked notifications

    The bell rings with decaying amplitude. Toasts stack in depth, fan out on hover and can be flicked away.

    • RationaleDepth keeps recent messages prominent; fan-out on hover or focus makes the stack inspectable.
    • TimingThe bell’s swing decays. Auto-dismiss uses real elapsed time and pauses during inspection, independently of decorative motion.
    • MechanismStack index controls translation, scale and opacity. Swipe gestures or each close button dismiss a toast and update the badge.
